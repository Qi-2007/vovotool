# PC 输入下偶发的镜头极慢

2026-11-15，当前国服 ARM64 7.2，修复版本 0.1.25。

## 现场与定位

用户报告鼠标、触控板和触屏都无法正常转动视角，进一步确认为“极其的慢”；修改分辨率前也偶发。先保留进程读取现场，没有用重启清除异常再推测原因。

现场 PC 输入模式仍为 2、设备类型为 1、指针捕获和窗口焦点正常。模块基础倍率为 0.01，Rewired InputBehavior 的鼠标轴倍率为 1，轴校准倍率也为 1。TpsCameraSensitivity 的设置索引没有归零。

只读短时采样显示，送入模块的像素位移最大约 203，经现有 0.01 缩放后到 ControllerDataUpdater 的轴值约 2.03，比例符合设置。因此该段没有丢失位移或意外增加额外缩放。

游戏 InputManager (`MHCNPJOGAGH`) 当时有：

| 字段 | 现场值 |
|---|---|
| `+12c` 原生速度参数 | 10 |
| `+14c/+150` 源换算系数 | 0.00064265949 / 0.00064265949 |
| `+170/+174` 镜头缓存 | 0.00032132975 / 0.00032132975 |
| 当前有效 DPI | 389.00848 |

原生刷新路径在键鼠模式计算 `speed / 40 / dpi`，再乘游戏的横、纵灵敏度设置，得到上述小系数。模块捕获的位移已经是像素，和该刷新路径期望的输入单位不匹配。异常与特定分辨率不是同一问题；分辨率变化可能参与 DPI 缓存更新，但本轮没有捕获到最初触发那一次异常的完整事件顺序。

在同一进程做了可恢复的对照：只把镜头缓存提高 10 倍，用户确认明显变快但仍慢；随后撤销该试验，把源系数恢复到像素基准 1，镜头缓存恢复到保留游戏比例的 0.5/0.5，用户确认“速度正常，略快一点点”。没有通过更改模块的 0.01 设置来掩盖这个状态差异。

## 正式实现

`look_sensitivity.hpp` 在以下原生函数执行完后修正单位：

| 入口 | RVA |
|---|---|
| 灵敏度重新计算 | `0xe1cb71c` |
| 横向设置更新 | `0xe1d35b8` |
| 纵向设置更新 | `0xe1d7ccc` |
| 原生速度更新 | `0xe1d2d64` |
| 读取游戏原生每轴设置，直接调用，不 hook | `0xe1cb88c` |

修正只作用于模块启用且已应用 PC 输入的当前 InputManager、模式 2。通过游戏原 getter 读取两轴设置，以默认速度参数 10 为像素基准，计算 `source = speed / 10`、`cacheX = source * nativeX`、`cacheY = source * nativeY`。保留原生速度变化、横纵差异及设置值为 0 的情况，保留原有模块倍率、触控板独立倍率和反转设置。

入口、源字段布局和构造函数中默认速度 10 的指令均纳入独立 `lookPins`。校验失败时不写字段；未知、非有限或超界值拒绝处理。没有对只有 12 字节的 Vector2 getter/setter 做 16 字节 inline hook。

初次接入、新 InputManager 身份出现时修正一次；其他时候在上述原生重算之后修正，没有每帧强写这组缓存。关闭模块时按原模式调用原生刷新，恢复原生单位计算。

`lookState` 为 12 项：状态、发生修正次数、重算次数、最近入口编号、源 X/Y、缓存 X/Y、原生速度、当前模式、代码校验通过、待处理诊断请求。浮点数按 1,000,000 倍报告。入口编号 0 为首次接入、1 为刷新、2/3 为横/纵设置、4 为速度。状态 2 正常，-1 指纹失败、-2 hook 安装失败、-3 输入值不支持。

root 或模块自身可调用 provider 的 `recalculate_look`。请求由游戏 Tick 执行原来的刷新入口，不更改用户设置，用来验证“重算后再次变慢”的回归。其他调用者不能请求该诊断。

## 验证

- 独立 ARM64 `tests/look_sensitivity_test.cpp`：晚发生的 DPI 重算、连续五次刷新、横纵设置分别变化、原生速度保留、触屏模式/模块关闭透传、关闭后恢复、一次性刷新请求、零灵敏度与无效值保护。
- 实机主动触发三次原生重算，每次观察到先经过原刷新，再修正回 source=1/1、cache=0.5/0.5；计数依次增加，没有累乘放大。
- 用户在重启后的正式模块上确认鼠标/触控板镜头正常。
- 同时验证当前已保存的 3200×2000 设置：三帧成功提交的几何、HDR 后处理、最终场景及输出均为 3200×2000，无命令丢失。游戏保存的 `20261115210157.png` 为 3200×2000；读回范围正常、资源错误为 0，用户确认照片没有此前的异常。

本地证据包括 `build/look-fix-native-refresh.json`、`look-unit-normalization-test.json`、`render-probe-3200-native-world.json`、`photo-native-3200.png` 和 `verified-look-and-native-photo-0.1.25.json`。旧进程里的手动试验字段已随该进程退出销毁。未记录账号凭据，没有修改游戏文件或系统分区。

本轮验证不能保证所有秘境、活动镜头和长时间运行都不会复发；如果再次出现，应保留现场并检查 lookState 及是否有新的系数写入路径，而不是继续提高用户倍率。
